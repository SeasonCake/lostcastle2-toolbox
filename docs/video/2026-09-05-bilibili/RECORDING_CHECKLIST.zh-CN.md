# 录制前只需注意这些

> 2026-09-05前期记录，现已作为历史制作资料保留；最终成片、发布状态及署名以[视频首页](README.zh-CN.md)和实际产品目录为准。

目标：约 40 分钟原片，由后期剪成约 3 分钟。可以自然演示，不需要一次讲完所有口播；旁白会后期按选好的画面制作。

## 最重要：先做 15 秒试录

先录一小段，同时出现游戏、工具箱 HUD 和按键浮层，按几下键、造成一次伤害，再回看文件。确认两个浮层真的被录进去、数值能读、声音正常。

盒子浮层是独立桌面窗口。仅使用“游戏捕获”时不能默认它们会被录入；可选捕获游戏所在显示器，或在录制场景里组合游戏与浮层窗口。使用显示器捕获时，只录游戏所在屏幕，先关掉聊天通知，避免副屏浏览器、个人路径与消息进入画面。依据：[OBS 捕获源说明](https://obsproject.com/kb/sources-guide)。

## 画面与声音

- 横屏 16:9，建议 1080p60；若设备负载允许且原生为 1440p，也可录 1440p60。不必为了此片上 4K。
- HUD 和按键窗要清晰，但别盖住人物、Boss 血条或主要战斗区域；预留底部字幕空间。切换功能时鼠标慢一点，点击后停 2—3 秒。
- 保留游戏音效；游戏内音乐适度调低或关闭，方便后期铺一套统一 BGM。不用边录边播放其他背景音乐。
- 如果用 OBS，多音轨建议：轨 1 混合参考、轨 2 麦克风、轨 3 游戏音频。检查各来源实际分配，不要只勾选三个相同混音轨。[OBS 多音轨指南](https://obsproject.com/kb/multiple-audio-track-recording-guide)。只有一轨也能做，后期调音空间会较小。
- 使用你已经稳定的录制方案即可；若使用 OBS，可录 MKV，结束后按需 remux 成 MP4，原文件保留。
- 可在精彩点后说“这段保留”或记一下大概时间。不强求边打边记；有时间点会更快找到清房与 Boss 精彩动作。

## 一局里尽量收齐的镜头

| 镜头 | 建议原始长度 | 需要看清什么 |
| --- | --- | --- |
| 开头 | 20—30 秒 | 盒子名称/版本、打开 HUD、进入游戏或关卡 |
| 普通清房 | 2—3 段，每段完整录下 | 怪物出现 → 战斗 → 清理结束；HUD 同时变化 |
| 实时监测讲解 | 20—40 秒 | 稳定小窗、点开详情、返回实战；至少一次连续更新 |
| 宏演示 | 30—60 秒，可在开打前补录 | 新建空白 → 添加步骤 → 启用 → 游戏里执行；最好也拍停止 |
| 按键显示 | 15—25 秒 | 按下/松开、与人物动作同屏、隐藏/显示各一次 |
| 增强计划 | 30—60 秒 | 面板标题、选择的功能、回游戏后的实际效果；作者按实际面板署名 |
| 第二个 MOD，可选 | 20—40 秒 | 一个明确效果即可；例如啵啵法杖，使用什么以实际为准 |
| Boss | 完整录制至少一场 | 起手、中段躲招/输出、最后阶段与结尾，不要在打完瞬间停录 |
| 结尾 | 20—30 秒 | 完整结算停留至少 5 秒，再回营/收尾；失败结算也可以保留 |

不必重装已经装好的 MOD 来凑镜头。若要展示“一键安装”，可在游戏启动前录一个实际需要安装的条目，后期保留几秒；运行中安装又需重启的场景按真实流程拍。

## 原片交接

录好后给出实际视频路径即可。若分成几段，按录制顺序提供文件名；如有“这个 Boss 一定保留”或“某段别放”的位置，一并标注。

请保留原始质量文件，避免先经聊天软件二次压缩。原片和后期代理分开；剪辑只对副本/代理操作，原片不覆盖。按 20 Mbps 举例，40 分钟视频约 6 GB，仅供预估；真实占用取决于编码模式和画面复杂度。

后期先索引再选镜，一个重处理任务逐步执行，避免录制/游戏时同时跑全片转码。交付前再核对成片中的聊天、昵称、个人路径、作者字幕、音量和获取链接。
