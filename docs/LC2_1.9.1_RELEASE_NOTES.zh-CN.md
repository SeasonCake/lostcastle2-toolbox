# 失落城堡2工具箱 1.9.1 更新说明

1.9.1 修复已有 BepInEx 的更新入口，并完善 HUD 队伍小窗。MOD 目录沿用 1.9.0 的84项社区条目，本版没有新增 MOD，也没有改动承伤、回复或法力计数公式。

2026-10-11，群分享包已完成本地交付，GitHub [v1.9.1 public-core](https://github.com/SeasonCake/lostcastle2-toolbox/releases/tag/v1.9.1) 已公开发布。

## 更新内容

- 启动游戏或安装 MOD 时，检测到不同版本的 BepInEx 核心会自动备份并更新为配套版本，不再询问是否覆盖。已有插件和配置保留，写入失败恢复原文件；游戏运行或进程状态无法确认时仍阻止 DLL 替换。首次初始化与单独组件升级保留原有提示。
- 队伍小窗分为“状态 / 背包 / 刻印”，保留当前成员和页签，避免信息堆叠。当前生命与法力使用数值和状态条；资源未同步与真实零值分开显示。
- 修复显示器缩放下随身资源被底部裁掉的问题。窗口按实际内容补足高度，保留字体和宽度；当前150%缩放样本为450×542物理像素。
- 标题、状态文字、资源和空白区域均可拖动小窗；按钮、列表和滚动条继续执行各自操作。HUD“队伍”与“盒子”分别控制小窗和完整主界面，保留半透明及锁定穿透。
- 清理圆角卡片关闭后的延迟布局回调，避免销毁窗口时出现 Tk 回调异常。

## 使用与验证范围

完整解压到新目录，退出旧版后运行“失落城堡2工具箱.exe”，保留整个 `_internal`。需要保留盒子设置时，可复制旧包 `config`，不覆盖新版程序目录。更新游戏组件前请完全退出游戏。

队伍读取默认关闭，配装助手默认可查看；配装修改仍需手动确认并在营地执行。建议在新开一局前启动工具箱，中途重启可能缺少此前累计数据。

- 源码全量491项测试通过，无失败或跳过；源码自检通过。
- 2、3、4人回放覆盖本机位于P1及非P1、逐玩家伤害/Boss伤害/占比、正式结算校正。真实 HUD 与队伍小窗同时刷新，切换成员、页签、开关、拖动及队伍数据过期均未改变战斗累计。
- 单人运行观察中 HUD 显示与当前聚合统计一致；四次游戏前台的页签点击保持游戏前台，主盒子维持最小化。这不等于所有显示模式和鼠标操作组合均已实测。
- 最新源码小窗在150%系统缩放下进行了实际窗口检查：大额金币、两行资源完整显示，背包及刻印详情可读，拖动资源文字仅移动小窗。画面使用标明的演示数据。
- 最终群包 EXE 在150%系统缩放下再次检查：HUD自动显示、队伍读取默认关闭，未同步资源与零值分别显示；资源两行完整可见，资源文字拖动只移动小窗。原图300×361与物理窗口450×542匹配，截图绑定最终EXE，9个选定控件的边界检查通过。画面使用演示数据，未冒充实机联机。
- 自动更新入口在隔离目录验证了不同运行库的直接替换、备份与用户文件保留、游戏运行/状态未知时拒绝写入以及写入失败回滚。
- 两种EXE自检通过；各自10个关键嵌入模块与核验源码一致。群包1,801个文件、90个社区功能文件；public-core为1,713个文件、不带社区载荷。两份ZIP的全部成员CRC、大小与SHA-256均匹配冻结目录，错误哈希样本被拒绝；桌面群包回读一致。

本次真实多人联机停在加载阶段，原因未确证，随后按作者决定改为单人测试；不宣称真实多人联机通过。所有MOD组合、不同显示器与游戏显示模式、public-core真实首次游戏启动和联网生成兼容文件流程也未逐一重测。

群分享包包含作者选择的社区载荷；GitHub public-core包含工具箱、自有组件、官方运行环境和目录元数据，第三方MOD/修改器载荷由用户自行提供。两种包分别核验，不共用校验值。

自有队伍/配装组件仍为1.9.0，战斗 Bridge 仍为1.7.4；本次没有改动游戏侧 DLL 的逻辑。原始校验与运行记录保存在本地 `artifacts/release/2026-10-11-v191/`，不随公开源代码或发行包上传。
