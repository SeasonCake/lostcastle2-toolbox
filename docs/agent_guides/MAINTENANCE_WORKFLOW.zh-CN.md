# 维护与调查工作流

> lifecycle: current / local-maintenance-entry
>
> 本入口只约束当前被选择的维护动作，不改变产品 CURRENT、版本资格或发布权限。

## 1. 计划 → 执行 → 核对

1. 先核当前请求、最近的 AGENTS、Git/dirty 和直接相关记录。摘要是定位线索，不是现状。
2. 写清必须改、必须保持、禁止触碰；选一个能推翻首要假设的最便宜检查。
3. 从实际样本/代码路径回投事实、推断与未知；成功搜索、数值一致或最终截图不能替代生命周期证据。
4. 只提交 own 路径；检查、文档提交、候选、部署和发布分别报告。不要为维护试点运行产品测试/构建。

范围、行为、负责人或下一阶段有实质分歧时，调用当前宿主允许的原生问答工具。
本机可用的 intent-checkpoint 技能提供流程；先读实际 SKILL 和工具 schema。异步表单的预选、
超时或卡片关闭不是用户答案。用户已明确的可逆终点继续做，明确保留的下一阶段保持等待。
没有可用表单时用一个简短问题，不新建表单系统。可选防护工程先选范围，不擅自加为发布门。

## 2. 有界检索入口

优先精确文件、该项目 Git tracked index 或一次浅层目录清单。不得默认扫描磁盘、工作区、
用户/Temp 根、全部 worktree、整个 scratch 或 Codex 历史。文件名 glob 和输出截断不是遍历预算。

正常 rg、多个具名目录、仓库内整体问题和大文件调查仍然允许，不因范围较大自动增加审批。
按问题选完整相关 corpus，再由代表样本估时设置预算；不要为迁就小工具而漏掉 caller/反例。
下述轻量助手的128文件/总正文16 MiB/单文件2 MiB硬上限不是全项目限制，更不是实测硬件阈值。
超出其适用范围时用合适的原生搜索，保持精确根或tracked文件集、排除项、低并发和实际deadline。
可回收进程的硬超时与exec的yield间隔不同；不能绕宿主阻止，也不能把helper拒绝写成正常任务不允许。

本项目携带 stdlib 工具 [bounded_readonly.py](../../scripts/maintenance/bounded_readonly.py)；
它是显式调用的辅助工具，不是系统级拦截器，不保证其他命令自动受限。在项目根目录运行：

```powershell
py -3 -B scripts/maintenance/bounded_readonly.py search --root (Get-Location).Path --file AGENTS.md --contains "scope" --max-bytes 65536 --timeout 10
py -3 -B scripts/maintenance/tests/test_bounded_readonly.py -v
```

search 只读具名 UTF-8 文本叶子，预检全部输入后才读正文，输出 SHA/命中行号而非整段内容。
默认最多 128 文件、每文件 1 MiB、正文总量 4 MiB、单行 64 KiB、输出 64 KiB、10 秒。
inventory 只在精确选定的非仓库根目录统计元数据，默认 4096 entries / depth 8 / 10 秒；
拒绝 reparse 路线，预算达到则返回 partial，不能拿 partial/timeout/no-locator 证明不存在。
exit 0 是本次完整执行，2 是 partial/timeout/limit，3 是 refused/error；零命中只限本次文件范围。

先测一个浅/深代表样本再扩大；单次重 I/O、硬超时、续接现有句柄。取消后核 owned worker 已退出。
工具不会写输入、删除、打包或授权清理；inventory 完整也不代表 cleanup eligible。
工具维护源来自治理工作树的同名脚本，升级按差异、SHA 与本地聚焦正反例同步，不能无审查覆盖本地改动。

## 3. 记录、空间与任务整合

内部记录保留普通路径、文件名、哈希、样本来源与恢复入口。信息按内容/去向分类，
不要把所有定位元数据标成 secret；对外视图另行派生，不反向删掉内部证据。
产品文案说明内容、位置、状态、下一步；处理细节放相应文档，不因调整文案删除底层控制。

清理先冻结精确绝对目标、条目/字节、归属、reparse/链接、实际占用、唯一证据与恢复源，
再执行被选择的处置并核保留对象。逻辑字节不等于实际回收空间。失败不能换语言扩大删除。
普通问答/小修复复用现有负责人；需要独立高风险审计时保持唯一正式 owner，不机械多开窗口。
归档前保留 handoff/唯一证据并核实际关联，归档可恢复不等于允许删除原始历史。

监测用现有低频任务或 owner 回投，真实变化才通知；通知前核原始证据与作者操作顺序，
不把观察改为实现。大上下文不代表全量加载历史；重启后重读当前入口并核 Git/产物，
由作者执行其明确保留的应用重启或下一阶段启动。
