# 版本与问题演进时间线

## 2026-08-26：从需求到可证伪合同

- 把宏、实时伤害、事件协议和 UI 分成独立层，先定义伤害、承伤、治疗、法力与房间生命周期口径。
- 明确不继承账号、激活、云同步、遥测等与免费本地工具无关的系统。
- 形成第一条长期原则：游戏 Hook、协议、聚合和界面必须能逐层对账。

## 2026-08-27：启动性能与恢复状态

- 用原版、BepInEx-only、BepInEx + Bridge 三臂实验拆分启动成本。
- 证据显示主要数秒级增量来自 BepInEx/Il2CppInterop，Bridge 未形成可辨认的额外回归；同时发现窗口模式与长白屏强相关。
- 实验首次把“测试结束后恢复原状态、回读文件身份、记录 NOT RUN”作为固定门。

## 2026-08-28—29：桌面产品、MOD 与署名边界

- v1.5.x 连续收口 HUD 位置、主窗口、MOD 安装、运行环境与分享包身份。
- MOD 管理从“复制 DLL”升级为最小功能载荷、来源登记、SHA-256、依赖检查和作者/上传者分离。
- 第三方伤害统计仅作为身份发现和官方数据源调查参考，没有直接移植其兜底算法。

## 2026-08-30：v1.6 与真实多人暴露

- 自动测试、包形和 UI 可以通过，但真实多人仍出现普通怪少算、owner 误归属与队友退出状态问题。
- 由此冻结规则：合成样本只能证明实现符合模型，不能替代宿主/客机、掉线、变身、召唤和自然结算的真实正控。

## 2026-08-31：r2—r6，官方槽位与会话边界

- r2 暴露官方 record 全部塌缩到本机槽位；根因是把 `mID` 当作玩家网络身份。
- r3 改用 `mIndex` 后仍证明最终记录生命周期与房内轮询不同，不能把临时字典当持续官方源。
- r4/r5 将 registered owner 覆盖、冲突、退出和 phantom session 分成独立门。
- r6 验证零实际伤害 fallback 只影响限定槽位，不能解释全部高算。

## 2026-09-01：r7—r11，final 冻结与跨局清理

- r7 用进程内随机 HMAC 将最终 record 与 roster 一一匹配，完整结算首次逐槽对齐；提前单独退局被判为无效测试路径而不是 PASS。
- P3 断线样本证明首次完整 final 必须冻结，后续 roster 收缩不能把已接受官方结果冲掉。
- r8 固化被动自然结算门；r9/r10 的自动归档实验暴露旧 session 事件与新 session 摘要串局。
- r11 将“新 session 明确清空旧内存状态”固定为产品合同。归档功能后来因每局写盘体量和群友磁盘风险在 v1.7 正式版移除。

## 2026-09-01：r12—r20，实时过程与官方结算分层

- r12—r15 证明 `mAdventureRecordDataList` 适合结算锚点，但房内可能冻结；NPC 额外 record 不能强塞给玩家。
- r18/r19 的只读限频探针发现 Statistics cache-list 在同房内逐玩家单调增长，`active + cache` 能在房间切换时守恒。
- r20 把过程值、房间 rollover、离队身份和最终官方值拆开；过程值可实时展示，SyncEnd final 允许向上或向下校正。

## 2026-09-02：r22—r23 与正式 v1.7

- r22 完成宏按键直接录入、60 秒默认时限、前台安全暂停和多 DPI 可见验收，同时扩展社区 MOD 清单。
- r23 完成四人高延迟撤退与双人自然结算矩阵，证明 realtime、owner、rollover、Boss 和双向 final 校正；游戏侧符文异常被独立记录，没有冒充工具箱 PASS/FAIL。
- 正式 v1.7 关闭高频诊断探针，移除逐事件 journal、每局 ZIP 和手动导出；仅保留内存态并在新局开始时清空。
- Mini HUD 使用短标签“实时”，异常时“实时 · 跳过”，完整 SyncEnd 后为“官方”；详细界面保留“实时估算/结算可能校正”。
- 全新、没有 BepInEx 的游戏环境可由工具箱安装并校验固定运行时；重复安装保持幂等。
- GitHub 技术记录继续保留 `rxx` 作为演进索引，正式版本号、包名、Release 标题和群公告统一为 `1.7`。

## 2026-09-02：v1.7.1 社区 MOD 刷新

- 在不修改 Bridge 1.7.0 插件版本和战斗统计逻辑的前提下，将群分享应用版本提升到 1.7.1；Release 隐私重编译移除了 DLL 中的本机 PDB 绝对路径。
- 怪物宝藏升级到 11.6，召唤大师来源升级到 2.5；新增啵啵法杖、磁暴线圈召唤啵啵和雷神之锤召唤愤怒雷精灵。
- 通过插件 GUID、程序集、大小和 SHA-256 区分真实升级、字节相同的来源迁移、独立旧功能与应排除的重复输入。
- 海克斯强化药水作者由早期误录更正为繁体 `時間與你`，并沿来源、catalog、包和 UI 全链核对。
- 啵啵法杖作者按维护者确认的 QQ 昵称记录为 `啊 这`；最终分享包与截图均重新生成，没有沿用“社区未署名”的旧候选。

## 2026-09-03：v1.7.2 DPS 维护候选

- v1.7.1 发布后，群友确认启动、MOD 添加和基本运行链可用；第三方 MOD 实战效果仍不外推。
- 单人反馈暴露 DPS 与总伤害的数据源不一致：总伤害能由 live 累计恢复，DPS 仅依赖逐击且首段固定除以 10。
- 早期 v1.7.2 四人房中两名路人逐渐离开，最终活动分母正确收缩；低频日志只确认一次 `damage_snapshot_missing`，不足以反推具体漏击或漏量。
- v1.7.2 桌面端改用 live 正差分优先、逐击尾段/回退、首段实际分母和重连重建；总伤害/final 与 MOD 合同不变。
- 未明确发布时默认构建 `Diagnostic`：匿名逐事件记录可暂停并手动导出；只有明确分享时才构建无归档、无诊断控件的 `Distribution`。Bridge 1.7.1 从同一源码生成互斥档位，缺失或交叉不一致会拒绝启动。
- “有事件跳过”从 Mini HUD 移除，只在详细页保留当前区与紧接的下一区。首轮诊断控件占高挤压明细表，最终移入明细标题栏并完成最小/常用尺寸像素验收。
- r2单人实测中途退出前全程skip/fatal/reset为0；最终4,935条匿名事件全部可重放且关键摘要差异0，DPS无负值/非有限值。退出回营没有`session_ended`，需manual export或下次启动恢复partial，记录为`MIDRUN-END-01`而不冒充自然结算PASS。

## 2026-09-03：v1.7.4 结算字段与发布包收口

- 多路检索确认结算record的三个确定字段为`mDamageValue`、`mBossDamageValue`、`mTakeDamageValue`，并从原生调用链定位到`UpdateSettlementInfo(__0)`及同链`SetSettlementData._selfPlayerData`；这解释了r5“UI已显示、save-list仍空”的失败。
