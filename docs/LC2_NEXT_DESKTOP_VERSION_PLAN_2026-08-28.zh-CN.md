## 1. HUD 默认左上角

### 已确认

- 当前默认：`x = (screen_width - hud_width) / 2`，`y = screen_height - hud_height - 90`，即屏幕中下方。
- 当前 HUD 没有跨重启保存坐标的配置；拖动只改变当前窗口，同进程缩放会尽量保留当前位置。
- 因此下一版最窄语义是“修改首次创建默认值”，不是迁移或覆盖所谓已有保存坐标。

### 实施约束与验收臂

- 默认放到主屏幕左上安全边距，边距在实现阶段结合 Tk scaling 冻结，候选范围为 10–24 逻辑像素。
- 保留拖动、隐藏/恢复、始终置顶和 0.85–1.25 HUD 缩放行为；不新增坐标持久化。
- 覆盖 100%/125%/150%/175%/200% DPI、普通值/千倍值、1280×720 与 1920×1080 代表屏幕。
- 正控：无历史窗口实例时出现在左上；反控：拖动后隐藏/恢复不跳回默认，缩放后仍在屏幕内且尽量保留拖动位置。

## 2. MOD 列表排版

### 已确认原因

- 当前 Treeview 列定义：名称 190px 可伸缩、版本 58px 固定居中、作者 105px 可伸缩左对齐、状态 78px 固定居中。
- 截图不是单纯“字体不好看”；主要问题是版本列太窄且相邻列采用相向对齐，版本值与作者值之间缺少稳定留白。

### 下一版方向

- 维持四列和当前信息顺序，不改成卡片、不删除版本或署名。
- 优先通过列宽分配解决：版本列提高到稳定可读宽度，署名列取得更大的最小宽度，名称列继续承担主要伸缩；不得在真实数据前拼空格制造假间距。
- 若最小窗口无法同时保留完整四列，应建立按 Treeview 实际宽度分配的几何函数，而不是靠单一固定像素在所有 DPI 下硬撑。
- 验收覆盖 46+ 条目、空搜索/命中/无结果、短署名、`社区未署名`、`兔子王お`、`空容、昕（修改）` 和更长拉丁/CJK 署名；覆盖 640×480 最小窗口及 100%/125%/150%/175% DPI。
