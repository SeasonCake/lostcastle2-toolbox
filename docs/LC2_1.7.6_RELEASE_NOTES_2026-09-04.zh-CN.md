## 本次变化

- 修复主界面首次打开 HUD 时操作区被说明文字挤压、按钮只能显示一部分的问题。
- 修复按键悬浮窗首次显示偶发无响应的问题：启动时先吸收仍处于按下状态的功能键，不再把它误判为一次新热键；启动显示改为明确的 show，不再被中途状态反向切换。游戏重新获得前台后会以不抢焦点的方式恢复置顶，并支持副屏及负坐标显示器的工作区夹取。
- 宏“新建”现在从空动作列表开始，不再自动带入“按一下、等待、按一下”的示例；切换未提交的步骤草稿时会明确提示，不再静默丢失。
- MOD 升级会清理目录中已登记且哈希完全匹配的旧版 DLL；修改过的文件、未知文件、目录、链接和越界目标均保留并停止覆盖。
- 正式 Distribution 继续关闭逐事件记录、自动对局归档和手动导出入口；当前局统计只保留在内存中，并在新会话开始时清空。

## 实战与承伤结论

- 2026-09-04 游戏更新后，BepInEx 首次启动重新生成 IL2CPP interop 缓存，窗口出现前等待明显变长；缓存完成后游戏正常打开。更新后的 interop 下 Bridge 重新编译为 0 warning / 0 error，既有 Bridge 字节保持不变。
- 单人完整实测覆盖一次 Alt+F4 强制退出、同房恢复和最终结算。旧段以独立 superseded 归档结束，新段从序列 0 和新的匿名 session 开始；两段共享 session/event 数均为 0，旧段承伤没有进入新段。
- 新段最终收到造成伤害、Boss 伤害和承伤三项官方值，随后收到真实 `session_ended`。最终显示与游戏结算一致，自动归档完整且无事件截断。
- 当前没有通过运行时证明的“官方局中承伤”来源。`mTakeDamageValue` 在最终 record 中存在，但活动 Statistics 记录只验证了造成伤害和 Boss 伤害；其承伤字段是否局中持续更新、跨房守恒并在回滚重进时正确复位尚未闭合。因此局中承伤继续使用过程估算，结算时由官方值原样覆盖。本轮样本中过程值为 242、最终官方值为 345；该差异不属于跨 session 污染，按非阻断已知边界处理。

## 已知边界

- 局中承伤是估算，可能在结算时向上或向下校正；造成伤害、Boss 伤害和 DPS 仍使用既有实时累计与逐击回退链。
- 本轮真实闭环是单人；多人终局、7—16 人房间和所有社区 MOD 组合效果没有重新实战。
- 游戏更新后首次生成 IL2CPP 缓存可能耗时较长；若游戏进程仍存在且没有错误提示，应先等待缓存完成，后续启动通常会恢复正常。
- 群分享版本已由维护者确认完成分发；GitHub `main`、`v1.7.6`、Latest Release、资产上传和公开下载回读均已完成。
