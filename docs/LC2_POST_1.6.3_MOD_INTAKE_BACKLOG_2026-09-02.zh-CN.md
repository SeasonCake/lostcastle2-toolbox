## 收录与部署审计合同

- 从老目录解析精确绝对路径，冻结文件名、类型、大小、SHA-256、修改时间和来源证据；压缩包须记录成员清单、编码和路径安全。
- 静态识别作者、版本、BepInPlugin 元数据、用途、热键、依赖、冲突和使用方法；来源信息不足时明确标记未知，不猜测。
- 只提取最小功能载荷；排除重复 BepInEx/core、Doorstop、cache、interop、生成配置、调试残留和路径穿越成员。
- 逐条核对公开再分发许可。无明确许可的二进制只允许本地导入/用户自备，不进入 GitHub 或 QQ 公开资产。
- 更新社区 catalog/source/notices 时保持显示、操作、来源与许可元数据分层；已有同系列条目先做字节/版本比较，避免重复收录或把来源迁移误记为升级。
- 为每个条目执行 known-good 安装/状态/卸载、篡改/冲突负控和未知文件保留测试；多文件包必须只移除登记叶文件。
- 重建候选后执行项目包与桌面包逐文件/目录一致性、fresh config、self-test、runtime fresh/conflict、许可证与说明回读。
- 部署前后结构化确认游戏和工具箱进程为 0；冻结旧版回滚身份，只部署精确候选；需要游戏行为确认的 MOD 另做最小真实烟测，不外推未测组合。
- 最终回执区分 source、candidate、package、desktop、installed、runtime smoke、commit/push/Release/QQ，各阶段不得互相代替。
