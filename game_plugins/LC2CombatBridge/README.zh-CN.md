# LC2 Combat Bridge

这是工具箱战斗统计的只读 BepInEx 6 IL2CPP 本地桥接插件。

- 只观察已验证的官方造成/承受伤害、有效 HP 恢复、房间生命周期和结算 checkpoint。
- 不修改游戏参数、返回值、存档、网络状态或战斗逻辑。
- 事件仅通过本机命名管道 `LostCastle2Toolbox.Combat.v2` 发送，不写战斗事件文件。
- 不采集昵称、Steam ID、平台账号、网络地址或聊天内容；实体编号仅作为本轮进程内的临时命中关联值。
- 队列、单行和事件字段均有上限。丢失快照、转换失败或队列溢出会将本轮标为错误，不继续显示伪实时统计。
- 当前 `0.4.1` 实现覆盖已有样本闭合的伤害和 HP 恢复；玩家官方承伤只接收玩家根实体作为 defender 的官方事件，排除同一回调中的召唤物承伤。游戏自身判定为非战斗房间时，目标伤害仍作为诊断事件发送，但不进入玩家可见的总伤害和 Boss 伤害。官方伤害结算之外的负向 HP 变化目前只作为内部候选事件保留，尚未覆盖伤势生命并完成实机闭合，因此不作为已完成的用户指标。房间位置在 `OnChangeRoomEnd` 后读取，废村入口实机已确认不再晚一房间。法力消耗仍通过官方 `OnUseMana` 观察，持续消耗按每个真实 tick 累计；0.4.0 诊断确认恢复事件包含小数，逐事件取整存在累计偏差风险，因此 0.4.1 改为传输并累计原始变化量，只在用户界面最终显示时统一取整。`OnRecoverMana` 的值是恢复后的目标 MP，不是增量，因此恢复量使用最近一次真实 MP 与回调后当前 MP 的原始差；若诅咒等状态使该官方回调缺席，已有底层 MP 前后观察会补记仍真实发生的正向变化，并按同一根操作扣除官方回调已覆盖的部分，避免双计。进图已满时差为 0，不会误计初始化。回营不会创建新统计会话，结算数据由桌面端保留到下一次真正进图。护盾及多人主客机权威性仍待独立取样。

构建需要 .NET 6 SDK、BepInEx 6 和当前游戏生成的 interop 程序集：

```powershell
dotnet build .\LC2CombatBridge.csproj -c Release -p:GameDir="<游戏目录>"
```

本地测试前，将生成的 `LC2CombatBridge.dll` 放入 `<游戏目录>\BepInEx\plugins\LC2CombatBridge\`。部署、游戏实测和发布是独立阶段；仅构建源码不会修改游戏目录。
