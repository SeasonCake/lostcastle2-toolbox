失落城堡 2 工具箱 · MOD 自动添加格式说明

一、普通用户怎么添加

1. 把一个 MOD 的 DLL、ZIP、7Z、RAR 或完整文件夹放进工具箱旁边的“用户MOD”文件夹。
2. 打开工具箱 → MOD 管理 → 点击“添加 MOD”。
3. 工具箱会静态读取文件名、DLL、随包说明和 lc2-mod.json，不会在识别阶段启动 MOD。
4. 检查识别出的名称、版本、作者、功能和使用方法；信息无误后确认添加。
5. 回到 MOD 管理列表，点击“一键安装”，再点击“启动游戏”。

自动识别适合常见的 BepInEx DLL 插件。包含 BepInEx 框架、winhttp.dll、游戏文件覆盖、超大载荷或不明确跨目录安装的包不会自动猜测，需先整理为下面的格式。

二、推荐的 lc2-mod.json

如果 MOD 作者已经提供清单，或自动识别的信息不完整，请把名为 lc2-mod.json 的 UTF-8 文件放在压缩包或文件夹内。示例：

{
  "schema_version": 1,
  "id": "my-lc2-mod",
  "display": {
    "name": "我的 LC2 MOD",
    "version": "1.0.0",
    "author": "作者名称；没有署名时填写社区未署名",
    "summary": "一句话说明 MOD 做什么",
    "usage_hint": "安装后启动游戏，按 F5 打开面板；保存后重新进图生效。"
  },
  "install": {
    "files": [
      "MyLc2Mod.dll",
      "libs/MyDependency.dll",
      "data/default.json"
    ]
  }
}

字段要求：

- schema_version：固定为 1。
- id：稳定且不重复，只使用小写英文字母、数字和连字符。
- display.name：给用户看的 MOD 名称。
- display.version：本包真实版本；同一 MOD 默认只保留最新可用版。
- display.author：只填写说明、源码或程序中能确认的署名；不能确认时填写“社区未署名”，不要猜。
- display.summary：一句话功能说明。
- display.usage_hint：写清启动后是否自动生效、快捷键、保存或重进游戏要求。
- install.files：只列这个 MOD 运行必需的文件，路径相对于压缩包或文件夹；不写电脑绝对路径，也不能包含 ..。

三、可以直接交给 AI 的提示词

请静态检查我提供的《失落城堡 2》MOD 压缩包或文件夹，不要执行其中的 EXE 或 DLL。请识别真正运行必需的 BepInEx 插件 DLL、同目录依赖和数据文件，排除源码、obj、ref、PDB、教程图片和重复构建产物。优先从 README、TXT、源码中的 BepInPlugin 信息和文件版本中提取 MOD 名称、版本、作者、功能与快捷键；没有作者证据时必须写“社区未署名”，不要猜测。请判断它是否包含 BepInEx 框架、winhttp.dll、游戏文件覆盖或跨目录配置；如有，请先说明，不能按普通 DLL 插件处理。最后只输出一个符合 schema_version 1 的 lc2-mod.json，id 仅使用小写字母、数字和连字符，install.files 只列运行必需文件并使用包内相对路径。

四、维护建议

- 同一个 MOD 有多个版本时，只把最新可用版放入“用户MOD”；测试、未完成或已知有 bug 的版本应在名称和说明中明确标注。
- 未提供 lc2-mod.json 时，如果一个包内只有同名主体加点分版本号的一组 DLL（例如 `实时数据1.1.dll`、`实时数据1.2.dll`、`实时数据1.3.dll`），工具箱会只选版本最高的一个；不同主体的版本化 DLL 不会被合并。
- 不要把整套 BepInEx 前置当成普通 MOD 添加。
- 不要让两个条目提供同名 DLL；工具箱会阻止已安装内容发生重复。
- 修改 lc2-mod.json 或替换 DLL 后，重新点击“添加 MOD”，让工具箱生成新的本地登记。
- 原压缩包不会被工具箱删除；添加成功后可自行移出“用户MOD”以保持目录整洁。
