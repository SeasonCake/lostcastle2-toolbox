## 0.4.10 策略

- 单个 damage/resource/MP/checkpoint 的 snapshot、conversion、stack 或容量问题改为 recoverable：跳过该事件、日志写出精确 code、桌面显示“实时 · 有事件跳过”，继续后续事件。
- 每种 recoverable code 每个 session 只通知一次，避免诊断自身形成事件洪水。
- 真正的 Bridge/桌面 queue overflow 仍进入“异常”，并明确记录 `Combat bridge session failed: queue_overflow`；不扩大队列掩盖问题。
- 该策略不声称已找到 0.4.9 的唯一 fault，只消除“一次局部事件令整局永久冻结”的产品缺陷，并为剩余致命路径提供可读证据。
